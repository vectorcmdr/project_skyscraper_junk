TAPE DECODE ANALYSIS SUMMARY
Theme: Punched Tape (2010: The Year We Make Contact - HAL 9000)
================================================================================

Methods explored:
  01: 8-Track Row-Major (standard ASCII per row)
  02: 8-Track Column Tape (5-bit frames per column)
  03: 7-Track + Sprocket (col 1 skipped, 7-bit ASCII)
  04: 5-Track Baudot (various column track sets)
  05: Baudot Column-Frame (Baudot decode of column frames)
  06: Continuous Tape (no block boundaries, 160-bit rows)
  07: Sprocket Stream (C1 bits extracted as data)
  08: 8-Track LSB-first (reversed bit order)
  09: 8-Track Bottom-to-top (reversed row order)
  10: 8-Track Column-Major (block order: column-first)
  11: Per-color Content Tape (individual color layers)
  12: Multi-Layer Tape (combined, XOR)
  13: IBM 7-Track (6-bit BCD + parity)
  14: 40-Bit Wide Frame (entire block = 1 frame)
  15: Serpentine Block Order (alternating direction)
  16: Corrupted Block Frames (only the 4 non-ERROR blocks)
  17: Reversed Tape (end-to-start frame order)

Data sources: background_ERROR, content_all (5 colors), combined, xor

Key findings:
  - Background grids produce clean 'ERROR' pattern = pure 0x00 bytes at C0,C2,C3,C5
  - Content grids are sparse (~13% filled) = mostly 0x00 frames
  - Combined (bg OR content) gives ERROR with occasional bit flips
  - XOR content vs bg = only the bit-flip positions
