============================================================================
BLOCK BIT OPERATION SHUFFLE 2 ELECTRIC BOOGALOO
============================================================================

Analysis of applying the QSRSV/ERR.R two-block interior transform ops
to various interpretations of the fragment image primary-blocks.

Assumptions:
image = payload (whole) -> 8x5 block = bytes payload -> 20x20 pixel blocks = bits
or
image = payload (whole) -> 8x5 block = bytes payload -> 20x20 pixel blocks = nibble packs -> 10x10 pixel blocks = bits


--- THE TRANSFORM OPERATION (T) ---

Derived from comparing (ERROR, ERROR) -> (QSRSV, ERR.R) at B1[7:8]:

```
T(left_5x8, right_5x8) -> (left', right'):
  LEFT':
    C3 = C1              (always-1 column duplicated into C3)
    C4 = 0               (zeroed)
    C5[0] = 0
    C5[r] = C4_old[r-1]  for r>=1   (old C4 shifted down)
    C7[1] |= right_C1[3]  (import bit from right block)
  RIGHT':
    C1[3] = 0             (lose bit at row 3 of C1)
```

--- META-BIT GRID TRANSFORM ---

Method 1: bg-decode differs from ERROR
- Only 2 non-zero meta-bits: B1[7]=QSRSV, B1[8]=ERR.R
- Transform applied: no change (too sparse to affect)
- Files: `meta_original_diff_from_ERROR.png`, `meta_transformed_diff_from_ERROR.png`

Method 2: has Content pixels
- B0-B9: all blocks have content EXCEPT B0[0], B0[9], B1[7], B1[0], B1[9]
- Transform changes 12/100 meta-bits (mostly C4 zeroing, C3=C1 copying)
- Key: B1[7] (QSRSV) is the ONLY block without content in its band — it's deliberately isolated
- Files: `meta_original_has_content.png`, `meta_transformed_has_content.png`

Method 3: Majority R-LSB of whole block
- B3-B9 form a complex pattern of 0/1 meta-bits
- Transform changes 11/100 bits — most visible effect
- Files: `meta_original_majority_R_LSB.png`, `meta_transformed_majority_R_LSB.png`

Method 4: R0C0 bit
- All zero — no transformation possible

Method 5: Row 0 != 'E'
- Only B1[7] has non-E row 0 (Q=0x51 != 0x45=E)
- Too sparse for visible transform effect

--- COLOR LAYER TRANSFORMS ---

- **Layer 0 (bg_dark)**: All 100 blocks become QSRSV/ERR.R pairs (just the forward transform on pure bg data)  
- **Layers 1-6 (content colors)**: All decode to non-printable '.' — content colors are too sparse within individual 20x20 dots to produce readable text
- Files in `layer_*_transformed.png` show the visual result for each color

--- OTHER APPLICATIONS ---

3a: Vertical transform (bands, not blocks)
- Produces alternating QSRSV/ERR.R vertically — same pattern, different axis
- Files: `reconstructed_vertical_transform.png`

3b: Connection image B-LSB transform
- Scattered non-printable characters, no readable text emerges
- The B-LSB data at the QSRSV position is mostly 1s, XORing doesn't produce QSRSV

3c: Nested transform (apply repeatedly)
- T^1: (QSRSV, ERR.R)  
- T^2: (QSRSR, ERR.R) — CONVERGES
- T^3+: (QSRSR, ERR.R) stable
- QSRSR = 0x51,0x53,0x52,0x53,0x52 = Q,S,R,S,R — the extra bit from right C1[3] gets incorporated into the left block

3d: Sliding window
- Files: `reconstructed_sliding_transform.png`

--- Content-affected blocks (ERVOR, E.ROR) ---
- ERVOR: single bit R2C5 flipped 0->1 by content overlay
- E.ROR: single bit R1C0 flipped 0->1 by content overlay  
- NOT the multi-column transform pattern — separate message layer

--- KEY FINDING: FULL INVERSE ANALYSIS ---

**ERROR IS at C3=[0,1,1,0,1], C5=[1,0,0,1,0] in the reconstruction space** — confirms QSRSV = T(ERROR, ERROR). The transform's input was genuinely ERROR; there's no hidden pre-image.

**ERR.R is pristine** — all 7 preserved columns match ERROR perfectly. Only C1[3] was zeroed. Reversing: just set C1[3]=1 to get ERROR back.
