1. EXECUTIVE SUMMARY

A comprehensive forensic audio analysis was performed on the file
self_introduction_memory_dump.mp3 using the same methodology that successfully
extracted the hidden message "journey" from the earlier ARG puzzle
tape_9_16_final_b_side.wav (forum post #704).

The core pipeline examined was:
  Hz → MIDI note number → direct ASCII / hex / NMS (Caesar) / cipher decode

In addition, the following techniques were applied:
  • High-resolution STFT spectrograms (focused 0–1200 Hz and log-scale)
  • Sustained-tone peak tracking with multiple FFT/hop configurations
  • pYIN fundamental-frequency extraction
  • Constant-Q transform (CQT) note tracking
  • Harmonic barcode extraction (audio-domain and image-domain)
  • Brute-force search over fundamental frequencies, harmonic counts,
    bandwidths, thresholds, bit orders, and offsets
  • Application of the known ARG monoalphabetic substitution cipher
    (KEY = MINDFAGEBJRLHCVPQSKYUWOXTZ)
  • High-band (500–4000 Hz) tone analysis
  • Raw MP3 byte-level string search and metadata inspection

2. CIPHER REFERENCE
================================================================================

  plaintext = KEY[ ciphertext_index ]

--------------------------------------------------------------------------------
Interpretation of low-band ASCII
--------------------------------------------------------------------------------
• The MONO string strongly suggests a structured path or code:
      OTK /// 2/3/2/3 - /2/34 -- /2/34 -- /2/34
  Removing separators gives: OTK 23232 234 234 234

• The numbers 320, 20, and 2 appear in the LEFT and RIGHT strings.
  In the prior ARG analysis (tapes_man/ANALYSIS_REPORT.txt) these were
  interpreted as:
    – .320  → post ID 320 (the 2017_dataset page)
    – /2/   → cassette label 2 (missing from the dataset labels)
    – .20   → memory segment 20

• The MONO string adds the repeating triplet 234, which was not present
  in either isolated channel. This suggests the combined (mono) view may
  contain an additional layer of information beyond the per-channel clues.

• The prefix "OTK" is consistent across RIGHT and MONO. Applying the
  known cipher yields "VYR", which does not match any known ARG keyword.
  It may be a label or an identifier rather than a ciphered word.

================================================================================
5. NMS / CAESAR TRANSFORM (MIDI % 26 + shift)
================================================================================

This is the exact technique that decoded "journey" from tape_9_16.
It was exhaustively tested on every channel (sustained tones, CQT, pYIN,
high-band) for all 26 shifts.

Best-scoring results (by vowel ratio + short-word matches):

  LEFT sustained  shift=2  → IZXXXWXWXWAYXWAYXWAYXWA
  RIGHT sustained shift=7  → INECFCFCZFCDZFCDZZFCDZZFCDZ
  MONO sustained  shift=7  → INECCCFCGCFCGACFCGHAACFCGHAACFCGH
  DIFF CQT        shift=16 → FEELLLLJLLJLLNJLLLNNJLLLNJLLP

Applying the cipher to the above NMS strings produces only gibberish
(e.g., shift=7 MONO decodes to BCFNNNANGNANGMNANGEMMNANGEMMNANGE).

No shift on any channel produces a recognizable English word or phrase.
This strongly implies that the hidden message is NOT encoded via the
MIDI%26+Caesar path for this particular file.
